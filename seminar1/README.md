# Практикум по алгоритмам и C++

Задания появляются в репозитории последовательно во время занятия.
Для работы нужен компилятор с поддержкой C++17 или новее. Можно использовать
привычную IDE; скрипты для работы с заданиями не требуются.

## Получение задания

1. Склонируйте репозиторий по ссылке преподавателя и откройте его папку.
2. Создайте в ней папки `solutions` и `build`.
3. Через файловый менеджер скопируйте выданный файл из `student` в `solutions`.
   Например, первое задание: `student/first.cpp` → `solutions/first.cpp`.
4. Редактируйте свою копию в `solutions`: заполните отмеченный `TODO`
   в функции `contains` в начале файла. Подключения и тип `Id` находятся
   перед ней; генерация данных, проверки и замеры — ниже пометки «Готовая часть».
   Если файл выдан как готовый пример, изучите функции в его начале.

Исходные заготовки в `student` оставляйте без изменений. Папки `solutions`
и `build` исключены из учёта Git, поэтому ваши решения и результаты сборки
не попадают в историю учебного репозитория.

## Следующее задание

По сигналу преподавателя выполните в терминале из корня репозитория:

```text
git pull --ff-only
```

Скопируйте новый файл из `student` в `solutions` и работайте с этой копией.
Если рабочая копия задания у вас уже есть, продолжайте редактировать её:
повторное копирование заготовки может перезаписать ваше решение.

## Сборка

Каждый файл `.cpp` — самостоятельная программа со своей функцией `main`.
Собирайте только один файл из `solutions` за раз. Не объединяйте все заготовки
и решения в одну программу.

В IDE выберите стандарт C++17 и конфигурацию Release с оптимизацией.
Передайте программе параметры запуска из раздела ниже.

Пример сборки первого задания с GCC или Clang из корня репозитория:

```text
c++ -std=c++17 -O3 -DNDEBUG solutions/first.cpp -o build/first
```

Если компилятор называется `g++`, используйте его вместо `c++`.
Для MinGW под Windows задайте имя результата `build/first.exe`.

Пример для MSVC из Developer Command Prompt, находясь в корне репозитория:

```text
cl /std:c++17 /O2 /EHsc /DNDEBUG solutions\first.cpp /Febuild\first.exe /Fobuild\first.obj
```

## Проверка и эксперимент

Сначала используйте небольшую проверку:

```text
--size 100000 --queries 1000 --sample-ms 50 --seed 20260929
```

Для сравнения результатов на занятии используйте одинаковые параметры:

```text
--size 1000000 --queries 10000 --sample-ms 250 --seed 20260929
```

Пример запуска на Linux или macOS:

```text
./build/first --size 1000000 --queries 10000 --sample-ms 250 --seed 20260929
```

Пример запуска в PowerShell на Windows:

```text
.\build\first.exe --size 1000000 --queries 10000 --sample-ms 250 --seed 20260929
```

В опыте половина запросов успешна, половина — нет. Перед замером программа
проверяет ответы. Пока `contains` возвращает заглушку `false`, программа
сообщает `contains failed an edge case`. После реализации функция должна
проходить проверки. Замер времени уже готов и не требует дописывания.

Параметр `--sample-ms` задаёт минимальную длительность одной серии,
а не ограничение времени всей программы. Каждая серия включает хотя бы
один полный проход по запросам.

## Результаты

Для каждого выданного задания запишите показатели программы:

| Показатель | Значение |
|---|---|
| `Build ms` | Время подготовки структуры поиска, миллисекунды |
| `Batch ms` | Время поиска по всему набору запросов, миллисекунды |
| `Total ms` | Сумма времени подготовки и поиска |
| `Data MiB` | Учтённая память структуры поиска, мебибайты |

Генерация данных и проверка ответов не входят в `Total ms`.
`Data MiB` не показывает пиковую память всего процесса.
Один МиБ равен 1 048 576 байтам.

Если программа выводит `Data MiB: not measured`, память структуры в этой
версии не подсчитывается. Запишите «не измерено» или используйте значение,
которое преподаватель покажет отдельно.

Сначала добейтесь правильных ответов, затем сравнивайте скорость и память.
